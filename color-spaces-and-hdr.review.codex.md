## Findings

1. **BLOCKER —** [ReactCommon/react/renderer/components/image/ImageShadowNode.cpp:241](/tmp/color-review/packages/react-native/ReactCommon/react/renderer/components/image/ImageShadowNode.cpp:241). **An ancestor update can mutate a sealed inline image with the flag off.** Mount a framework-backed inline `<img>` in a block container with `enableStringChildren=true`, then change the container’s inherited color while retaining the image child. The anonymous-box configure loop calls `setInheritedCascade` through a `const_cast` without cloning published attachments; the new setter calls `updateStateIfNeeded`, whose `ensureUnsealed()` asserts. Debug builds abort; release builds write into a shared revision. Neither the new consumer trait nor setter is gated by `enableColorSpaces`. Clone published attachments into the owning revision before updating state, and gate the new work.

2. **BLOCKER —** [React/CoreModules/RCTDisplayCapabilities.mm:125](/tmp/color-review/packages/react-native/React/CoreModules/RCTDisplayCapabilities.mm:125). **The synchronous capability getter races replacement of its dictionary.** A display-change notification assigns `_capabilities` on the main thread at line 119 while JS calls `getCapabilities` synchronously. `methodQueue` does not protect this: `RCTTurboModuleManager.mm:128` executes synchronous work directly. The unsynchronized strong-ivar read can race release of the old dictionary, creating a use-after-free hazard. Protect snapshot reads and replacement with the same lock.

3. **BLOCKER —** [Libraries/Utilities/matchMedia.js:89](/tmp/color-review/packages/react-native/Libraries/Utilities/matchMedia.js:89). **Listener accounting leaks lists and can disable active listeners.** `addEventListener('change', f)` twice followed by one removal leaves one retained count although `EventTarget` deduplicates the registration. Adding `null` or an already-aborted listener also retains the list; subsequently aborting a registered listener removes it internally without releasing this count. These lists remain strongly held in `watched` indefinitely. Conversely, removing a callback never registered can unwatch a list that still has listeners. Track actual registrations, including capture and abort cleanup, rather than counting calls.

4. **BLOCKER —** [Libraries/Animated/nodes/AnimatedInterpolation.js:191](/tmp/color-review/packages/react-native/Libraries/Animated/nodes/AnimatedInterpolation.js:191). **Modern color strings break Animated interpolation.** With the flag on, an output range containing `color(display-p3 1 0 0)` and `color(display-p3 0 0 1)` normalizes to objects and hits the unconditional “PlatformColors are not supported” invariant. The native configuration also recognizes only numeric `processColor` results; modern strings remain strings instead of becoming color values. The C++ native node’s numeric fallback then calls `asDouble()` on them. Implement rich-color interpolation and native configuration end to end.

5. **BLOCKER —** [Libraries/ActionSheetIOS/ActionSheetIOS.js:113](/tmp/color-review/packages/react-native/Libraries/ActionSheetIOS/ActionSheetIOS.js:113). **The new color wire crashes ActionSheetIOS callers.** Calling `showActionSheetWithOptions` with `tintColor: 'color(display-p3 1 0 0)'` now produces an object, violating the numeric invariant and throwing before presenting the sheet. The cancel and disabled tint options have the same problem. Update these JS contracts and their native specification to accept structured colors.

6. **HIGH —** [ReactCommon/react/renderer/graphics/platform/android/react/renderer/graphics/HostPlatformColor.h:200](/tmp/color-review/packages/react-native/ReactCommon/react/renderer/graphics/platform/android/react/renderer/graphics/HostPlatformColor.h:200). **Android transitions interpolate clipped approximations.** The component reader ignores the interned original and reads the eight-bit `.value`. The transient factory at line 194 clips the result again and discards its space. A transition between `color(srgb-linear 2 2 2)` and `color(srgb-linear 4 4 4)` therefore computes intermediate frames from SDR white, then returns the exact HDR endpoint at completion. Read the original extended components and retain transient rich values without filling the permanent table.

7. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/uimanager/style/LinearGradient.kt:64](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/uimanager/style/LinearGradient.kt:64). **Android gradients still discard color space and precision.** Rich stops, including the newly computed samples, pass through `ColorPropConverter.getColor`, which calls `toArgb()`. The shader receives an `IntArray` at line 146; radial gradients have the same integer pipeline. A Display P3 red-to-green gradient consequently cannot retain its authored gamut even in a wide window. Carry color longs through stop processing and shader construction, and request the required window mode.

8. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/uimanager/BaseViewManagerDelegate.kt:51](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/uimanager/BaseViewManagerDelegate.kt:51). **Several ordinary prop paths bypass the new long setters.** Generated delegates inherit this base delegate, which converts backgrounds to an integer and invokes the integer overload. Thus a P3 background on a component using such a delegate clips although the reflection path preserves it. Image border, overlay and tint setters also remain integer-only; outline colors remain integers, and text background, decoration and shadow colors still use `putInt` in `attributedstring/conversions.h`. Complete these paths, and declare genuine platform restrictions. The register’s claim that Android covers all color-long paints is insufficient.

9. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/bridge/ColorPropConverter.kt:47](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/bridge/ColorPropConverter.kt:47). **Predefined colors disappear when the OS lacks their space.** On supported API 24–25, even `color(srgb 1 0 0)` returns no color. On later systems, a missing predefined `ColorSpace.Named` similarly produces null instead of a CSS arithmetic fallback. Meanwhile, `CSS.supports` returns true for these predefined spaces. Implement the promised predefined-space fallback; reserve “unavailable” for dashed spaces without a CSS definition.

10. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/bridge/ColorSpaceColors.kt:245](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/bridge/ColorSpaceColors.kt:245). **Constructed linear spaces introduce clamping before packing.** `linearOf` uses the RGB constructor with the default `[0,1]` range, then `pack` converts through `ColorSpace.connect`. Consequently, `color(display-p3-linear 2 2 2)` and `color(rec2100-linear 2 2 2)` lose their extended values before reaching the paint. **Unverified on a device:** this consequence follows from the constructor and connector behavior in [AOSP’s ColorSpace implementation](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/graphics/java/android/graphics/ColorSpace.java). Use CSS arithmetic or an explicitly extended source range. Audit the native XYZ/Oklab conversions for their platform channel bounds as well.

11. **HIGH —** [ReactCommon/react/renderer/components/view/BaseViewProps.cpp:247](/tmp/color-review/packages/react-native/ReactCommon/react/renderer/components/view/BaseViewProps.cpp:247). **An iOS view’s own limit depends on an unrelated feature flag.** Enable color spaces while leaving `enableStringChildren=false`, then give a View an HDR background and `dynamicRangeLimit: 'standard'`. Both constructor parsing and the setter macro ignore this field without string children, so the layer reads the default `no-limit`. Parse the view’s own dynamic-range policy under the color-spaces flag independently of text inheritance.

12. **HIGH —** [React/Fabric/Mounting/ComponentViews/View/RCTViewComponentView.mm:1463](/tmp/color-review/packages/react-native/React/Fabric/Mounting/ComponentViews/View/RCTViewComponentView.mm:1463). **Changing only an iOS view’s limit leaves its previous layer policy installed.** Mount an HDR background with `no-limit`, then update only `dynamicRangeLimit` to `standard`. `updateProps` never compares `inheritedDynamicRangeLimit`, while the policy helper runs only during layer invalidation. With unchanged colors and layout, finalization returns early and the layer retains its old range. Include the policy in invalidation decisions.

13. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/uimanager/BaseViewManager.java:261](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/uimanager/BaseViewManager.java:261). **Android limit updates do not reconsider window requirements.** Mount an HDR color while its limit is `standard`, then change only the limit to `no-limit`. The setter only changes a tag; HDR requests occur when colors are assigned, so the existing color remains in the previous window mode. Initial prop ordering can also request HDR before the standard tag is installed. Evaluate effective policy after the prop transaction and on subsequent policy changes.

14. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/views/image/ReactImageManager.kt:307](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/views/image/ReactImageManager.kt:307). **Inherited image-limit changes are stored but not applied.** Change an ancestor from `standard` to `no-limit` while keeping the image’s props and layout unchanged. `updateState` dirties `ReactImageView` and returns null. `SurfaceMountingManager.updateState` neither runs `onAfterUpdateTransaction` nor calls `maybeUpdateView`; the HDR request occurs only on a final-image callback. A later unrelated prop update rebuilds the request, and `cache: 'reload'` even evicts and refetches it. Apply the policy to the existing image immediately without issuing another image request.

15. **HIGH —** [ReactAndroid/src/main/java/com/facebook/react/uimanager/WideColorGamut.kt:82](/tmp/color-review/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/uimanager/WideColorGamut.kt:82). **The luminance threshold misses extended saturated colors.** `color(srgb-linear 4 0 0)` has luminance about `0.8504`, so both this predicate and the iOS predicate classify it as SDR despite requesting four times SDR red’s intensity. Neither enters its HDR path. **Unverified on a real panel:** the resulting brightness loss depends on platform compositing. Determine whether a color requires extended display range rather than using white’s luminance as the sole threshold, while still distinguishing ordinary P3 red from HDR red.

16. **HIGH —** [packages/normalize-color/colorInterpolation.js:414](/tmp/color-review/packages/normalize-color/colorInterpolation.js:414). **HDR-space endpoints silently disable requested gradient interpolation.** The conversion switch has no `rec2100-linear`, PQ or HLG cases. For example, `linear-gradient(in oklab, color(rec2100-linear 1 0 0), black)` returns null from interpolation, causing `expandColorStops` to return the original stops and discard the requested method. This is separate from the declared length/hint restriction. Add the HDR conversions to the JS interpolation pipeline.

17. **HIGH —** [Libraries/Utilities/matchMedia.js:65](/tmp/color-review/packages/react-native/Libraries/Utilities/matchMedia.js:65). **Reading `matches` can swallow a change event.** Register an Appearance listener before the first watched media query; have it read that query’s `matches`. On a scheme change, Appearance updates its cache before notifying listeners. This getter overwrites the stored previous answer, so the later `__refresh` sees no change and suppresses the event. Return the live answer without overwriting the last-notified value.

18. **MEDIUM —** [React/Fabric/Mounting/ComponentViews/View/RCTViewComponentView.mm:1581](/tmp/color-review/packages/react-native/React/Fabric/Mounting/ComponentViews/View/RCTViewComponentView.mm:1581). **Recycling clears the HDR memo without resetting the surviving layer.** Recycle a plain View whose layer requested HDR, then reuse it for SDR content. Recycling sets `_layerWantsExtendedDynamicRange=NO` but leaves `preferredDynamicRange` or `wantsExtendedDynamicRangeContent` installed. The next SDR invalidation returns early because both `bright` and the memo are false. Reset the actual layer policy before clearing the memo, or preserve the memo until cleanup runs.

19. **MEDIUM —** [ReactCommon/react/renderer/graphics/platform/android/react/renderer/graphics/HostPlatformColor.h:119](/tmp/color-review/packages/react-native/ReactCommon/react/renderer/graphics/platform/android/react/renderer/graphics/HostPlatformColor.h:119). **Table exhaustion permanently downgrades subsequent colors.** Supply 65,535 distinct rich values over a long-lived process—for example, successive color-picker values—and unmount their views. Entries are never reclaimed. Later new colors receive index zero and become clipped approximations; unsupported dashed approximations become undefined. This fallback is not registered. Provide owned overflow storage or reclamation that preserves every live Color’s handle.

20. **MEDIUM —** [Libraries/Utilities/matchMedia.js:219](/tmp/color-review/packages/react-native/Libraries/Utilities/matchMedia.js:219). **Media-query negation and grammar are incorrect.** `not print` is marked invalid and returns false on a screen, while `not (unknown-feature: x)` negates false and returns true. Nested conditions and `or` are also not parsed. Unknown media types must remain distinguishable from invalid syntax, and unknown features require three-valued evaluation. Implement that distinction and the advertised condition grammar, or register the restrictions. See [Media Queries 5 evaluation and error handling](https://drafts.csswg.org/mediaqueries-5/#evaluating).

21. **MEDIUM —** [Libraries/StyleSheet/CSS.js:40](/tmp/color-review/packages/react-native/Libraries/StyleSheet/CSS.js:40). **CSS.supports reports unsupported properties as supported and rejects valid conditions.** `CSS.supports('made-up-color', 'red')` returns true solely because of the suffix. Conversely, `CSS.supports('color: red')` and `(color: red) and (color: blue)` return false despite the individually supported declaration. Property-name trimming also accepts names the API should reject. Validate supported property names and implement condition parsing, including implied parentheses; the deliberate grammar subset is absent from the register. See [CSS Conditional Rules’ supports algorithm](https://drafts.csswg.org/css-conditional-3/#the-css-namespace).

22. **MEDIUM —** [packages/normalize-color/colorSpaces.js:304](/tmp/color-review/packages/normalize-color/colorSpaces.js:304). **The tokenizer accepts invalid decimal syntax.** `color(srgb 1. 0 0)` consumes `1.` as a number and draws red, although CSS tokenizes the trailing dot separately and rejects the value. The whitespace scanner also rejects internal carriage returns and form feeds. Follow CSS number consumption and input preprocessing rather than this permissive regular expression and partial whitespace list. See [CSS Syntax’s number algorithm](https://drafts.csswg.org/css-syntax-3/#consume-number).

23. **MEDIUM —** [Libraries/Utilities/matchMedia.js:146](/tmp/color-review/packages/react-native/Libraries/Utilities/matchMedia.js:146). **`onchange` bypasses event dispatch semantics.** It runs before `dispatchEvent`, so its event has no media-query target/currentTarget. If the handler throws, registered listeners and subsequent watched lists are skipped. Register the event-handler attribute through the EventTarget machinery so targeting, ordering and exception handling match ordinary listeners.

24. **LOW —** [Libraries/StyleSheet/StyleSheetTypes.js:994](/tmp/color-review/packages/react-native/Libraries/StyleSheet/StyleSheetTypes.js:994). **Required public API snapshots were not regenerated.** The Flow surface adds `dynamicRangeLimit`, but `ReactNativeApi.d.ts` contains no such field. Android’s committed API snapshot similarly lacks the new boxed-Long background setter and other public additions. Regenerate the TypeScript and native API snapshots from their sources and run the repository’s required validation before submission.

## Checked, not raised

- **Flag-off integer handling:** normalization, gradient expansion and transition mixing retain their legacy branches; the Long prop path shifts and recovers ARGB correctly and still invokes integer overrides.
- **Android table integrity:** lookup uses value equality after hashing, indices remain stable, reads return copies under the mutex, and memory growth is bounded by capacity; exhaustion is finding 19.
- **iOS ownership and marking:** managed UIColor ownership is retained, and constructors explicitly set or clear the rich-color bit; no concrete new hash collision was demonstrated. Equality remains hash-only.
- **Threading:** the Core Graphics resolver is mutex-protected; Android’s ordinary JS queue has a prepared Looper, so I found no verified null-handler startup crash.
- **Cascade bookkeeping:** the new limit participates in `apply`, equality, hashing, inherited-prop detection and cascade-change detection; the image-manager null guard is present.
- **Image state:** the C++ limit-only state constructor shares the existing image request, and an unchanged default Android limit does not itself dirty the image.
- **Long overloads:** distinct applicator method names and the trailing BoxShadow field preserve existing integer and positional source calls.
- **HDR conversion guards:** iOS handles null matching results and checks component count before indexing; PQ fallback uses 203-nit reference white, and HLG fallback normalizes signal 0.75 to reference white.
- **Parser basics:** percentages, scientific notation, hue wrapping, alpha clamping, uppercase predefined names and comma rejection are implemented; `none` becoming zero is explicitly registered.
- **Interpolation basics:** premultiplied alpha and the four hue-adjustment branches are present; percentage-position fix-up handles decreasing and repeated stops without dividing by a zero-length stretch.
- **Media-query lifetime cases:** replacing `onchange` balances its count, and `once` removal routes through the overridden removal method correctly.
- **CSS.supports consistency:** `transparent` and uppercase supported property names work; rejected `currentColor`, `color-mix()` and `var()` values are also rejected by the color parser.
- **iOS layer ordering:** new props are installed before final invalidation, and a newly created background sublayer exists before its range policy is applied.
- **Android window handling:** activity lookup is not process-global and HDR requests do not downgrade an already-HDR window; sticky mode and shared image headroom are declared choices.
- **Register parity:** all five Color slugs have corresponding code markers. The declared missing-component, own-element limit, iOS SDR paint and length/hint restrictions were not raised again merely for being limitations.

## Verdict

**NOT READY** — the series needs its crash and lifetime defects fixed, color propagation completed, dynamic-range updates repaired, and remaining restrictions accurately registered before an upstream pull-request series.
