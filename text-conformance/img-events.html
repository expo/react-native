<img> is an inline replaced element: an atomic box inside a run of text, shifting the line's height the way a letter would. That is what separates it from a block-level <Image>.

Load events

loadstart, load and loadend fire as the image is fetched — the same lifecycle the DOM exposes.

The web and the native side do not report the same set here, and the difference is in the standard rather than in this engine: an <img> fires only load and error. loadstart and loadend are progress events — they belong to XMLHttpRequest and to the media elements, not to images — so a browser has nothing to dispatch for them. The native side reports the whole lifecycle because its image loader knows when the request began.
